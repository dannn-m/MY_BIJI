# 等价路由
- ospf 开销计算 cost＝100/实际带宽值
- 可以限制等价路由数目，默认为 8 个 max  loadbanlance
- 更改等价路由权重可以影响选路，越小越优先
# 缺省路由
- 手动生成
	- default－route－advertise  普通下发，只有默认路由路由才会神效
	- default－route－advertise  always  强制下发，有无默认路由都会生效
	- 一般都用普通下发，因为强制下发的话，链路断掉以后路由不会消失，数据包到达区域边界后路由不会消失，会丢弃数据包，浪费路由器的资源
	- 默认是 5 类 lsa
- 自动生成
	- 特殊区域产生，特殊区域只能在非骨干区域配置
	- stub：拒绝 4、5 类 lsa
	- total stub：拒绝 3、4、5 lsa
	- nass 
# LSA 过滤
- 过滤四五类 lsa
	- 对发送的 LSA 进行过滤
	- 非骨干区域可以配置末梢区域对 lsa 进行过滤
	- 骨干区域可以在**接口视图**下使用 ospf filter－lsa－out 对出方向进行过滤 （？查看过滤）
- 过滤三类 lsa
	- 需要用前缀列表或者，acl 等过滤工具
	- 可以在产生区域的出方向进行配置，也可在目的区域的入方向进行配置
	- 配置完过滤工具后在，区域视图敲 filter 匹配工具 i/e 生效
# OSPF Database Overflow
- 指的是由于路由器资源无法满足对 lsdb 的承载，使其超载
- 通过限制数据库规模来解决
	- lsdb－overflow－limit number
	- 限制非缺省外部路由的数量即 5 类 lsa
	- ospf 网络中的所有路由器都要配置相同的上限值，达到上限路由器进入 overflow 状态，并同时启动 overflow 状态定时器（缺省 5 s 超时，超时后退出）

| Overflow 状态阶段   | OSPF 处理流程                                                                                                                              |
| --------------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| 进入 Overflow 状态时 | - 路由器删除所有自己产生的非缺省外部路由；<br>- 启动 Overflow 状态定时器。                                                                                         |
| 处于 Overflow 状态中 | - 不产生非缺省外部路由；<br>- 丢弃新收到的非缺省外部路由，不回复确认报文；<br>- 当 Overflow 状态定时器超时，检查外部路由数量是否仍然超过上限：<br>  - N：退出 Overflow 状态；<br>  - Y：重启 Overflow 定时器。 |
| 退出 Overflow 状态时 | - 删除 Overflow 状态定时器；<br>- 产生非缺省外部路由；<br>- 接收新收到的非缺省外部路由，回复确认报文；<br>- 准备下一次进入 Overflow 状态。                                              |
