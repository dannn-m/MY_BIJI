- 相比单播不会导致信息负载的加重，不会导致网络资源显著增加

# 组播 mac
- 由组播 ip 映射而来
- 前 24 位固定 ox 01005 e 第 25 位为 0，后 23 位为 ip 地址的后 23 位
- 由于 d 类 ip 地址前 4 位固定 1110 ，23+4=27 则有 5 位信息丢失，有可能不同 ip 映射相同的 mac

# 组播服务类型
- ASM:组成员加入组播以后，组成员可以接收到任意源发送到该组的数据
- SSM:组成员加入组播 以后，组成员只接受特定源发送到该组的数据

# 转发原理
- 依据路由表项，也会有环路与次优问题
## 组播路由与 RPF 检查
- 组播路由表项还需添加组播源和入接口信息，设备==仅转发==从特定==唯一的入接口==收到的组播数据，避免环路，次优
- 对于相同组播源，通过 RPF（reverse path forwarding，反向路径转发）检查可以确定设备上唯一的组播流量入口
- 检查过程为，设备检查组播源的==单播路由==的出接口，若为此组播数据的入接口则检查成功，反之检查失败（不完整，RPF 不只来自单播路由）
**RPF 来源**
- 单播路由表、MBGP 路由表、组播静态路由表都是会成为 RPF 的备选
- 优选规则：
	- 最长掩码
	- 路由优先级
	- 组播静态>MBGP>单播 
## 组播协议
- 组播网络需要基于多种组播协议次啊能建立转发路径
	- IGMP：告知组播网络，组成员所在的位置与所加组播组
	- 工作在组播转发网络的协议有：
		- PIM（协议无关组播）：生成 as 域内的组播分法树
		- MSDP(组播源发现协议)：帮助生成 AS 域间的组播分发树
		- MBGP（组播 bgp）：帮助跨域组播流进行 RPF 校验
