> **概述**：在无法通过硬件系统检测故障的系统中，通常采用上层协议本身的 hello 报文机制检查测网络故障，检查测时间超过 1 s 钟，三层网络中静态无故障检测机制
# 报文结构
| 分类   | 字段            | 含义       | 默认值 / 取值                          |
| ---- | ------------- | -------- | --------------------------------- |
| 强制部分 | sta           | 本地状态     | BFD 四种邻居状态：down、init、up、adminDown |
| 强制部分 | detect mult   | 检测倍数     | 默认 3                              |
| 强制部分 | discriminator | 标识符      | 本地 local，远端 remote                |
| 强制部分 | min TX        | 最小发送间隔时间 | 默认 1000ms                         |
| 强制部分 | min RX        | 最小接收间隔时间 | 默认 1000ms                         |
| 可选部分 | —             | 主要用于认证   | —                                 |
# 会话
**建立**：
- 静态：命令行手动配置参数
- 动态：动态建立 BFD 本地会话的本地标识符触发创建
**状态**：
- 四种：DOWN,init，up，admindown
- BFD 状态机的建立和拆除都采用三次握手机制

# 检测模式
1、异步模式：
周期性的发送 BFD 控制包，若检测时间内没有收到对端发到的 BFD 的控制报文，就宣布会话 down
2、查询模式
在需要检查连接性的情况下，系统连续发送多个 BFD 控制包，检测时间内没有收到返回报文就宣布 down
# 检测时间 
**检测时长**由 TX,RX,DM 三个参数决定。
