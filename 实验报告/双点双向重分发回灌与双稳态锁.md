|---|---|---|
| R1 | 纯 OSPF | 1.1.1.1 |
| R2 | ASBR 双点双向 | 2.2.2.2 / 49.0001.0000.0000.0001.00 |

# 二、现象

R1 上 5.5.5.5 两条等价路由，下一跳是 R5（10.0.15.5）和 **R3（10.0.13.3）**，不是 R2（10.0.12.2）。

```
[R1] display ospf lsdb ase 5.5.5.5
  Adv rtr: 10.0.15.5   seq# 0x80000001   Tag 1   ← R5 直连注入
  Adv rtr: 3.3.3.3     seq# 0x80000006   Tag 1   ← R3 回灌
  （没有 2.2.2.2）
```

# 三、三层路由数据（一切讨论的地基）

| 层 | 命令 | 内容 | 用途 |
|---|---|---|---|
| **LSDB** | `display ospf lsdb` / `display isis lsdb` | 所有设备通告的原始 LSA/LSP | SPF 的原料 |
| **协议路由表** | `display ospf routing` / `display isis route` | 单协议 SPF 算出的候选集 | 交给 RIB 参选 |
| **RIB** | `display ip routing-table` | 跨协议比完后的裁决 | 下发 FIB，实际转发 |

R3 上三层**都有** 5.5.5.5，但重分发只认第三层。

## RIB 是唯一裁判

```
Direct 0 < OSPF 10 < IS-IS 15 < Static 60 < RIP 100 < OSPF ASE 150 < BGP 255
```

```
O_ASE     Pref 150   Cost 1     ← cost 只有 1
ISIS-L2   Pref 15    Cost 84    ← cost 高达 84
```

**IS-IS 赢不是因为路径短，而是因为 15 < 150。**

不同协议的 cost 是不同量纲（OSPF 是带宽倒数，IS-IS 是接口缺省值累加），**跨协议只比 preference，不比 cost**。pref 相同才比 cost，都相同才 ECMP。

## Active / Inactive / D 位

```
Active    = 选中，已下发 FIB，可转发，可重分发
Inactive  = 落选，保留在表里只作快速收敛备份，不可重分发
```

`Flags: D`（Download to FIB）= 胜出并生效。只有带 D 的条目能被重分发。

# 四、重分发的本质：无记忆的集合同步

## 谓词是合取，不是选择

`import-route ospf 1 route-policy X` 的真实判定是四项同时成立：

```
① RIB 里存在这个前缀          ← 存在性
② Proto == OSPF && PID == 1   ← 协议匹配
③ D 位 == 1                   ← 裁决状态
④ route-policy 结果 permit    ← 策略匹配
```

**route-policy 只是第 ④ 项，不能创造路由。** 条目不在 RIB，就没有求值对象，直接算未命中。

常见误解：以为 route-policy 是宣告清单（像 BGP 的 `network`）。实际上它是**白名单**，且**缺省拒绝**。

## 为什么要查 RIB，不用 LSDB / 协议表

| 理由 | 说明 |
|---|---|
| 只有 RIB 做跨协议比较 | preference 表只在 RIB 存在 |
| 导出必须等于转发现实 | 导出自己不走的路 → 对端送来流量 → 黑洞或环路 |
| 从 LSDB 导出必然成环 | LSDB 没有"已发过"的记忆，无刹车 |
| RIB 处理递归与下一跳可达性 | 下一跳不可达、出接口 down、被更具体前缀覆盖 |

> **重分发的语义：把我路由表里正在用的这条路翻译给你，而不是把我听说过的所有路都告诉你。**

不是华为特例：Cisco `redistribute`、JunOS `export policy`、FRR、BGP `network` 全部读 RIB。

## 协议没有"来源"字段

| 能看到 | 出处 | 本实验 |
|---|---|---|
| 哪个 System ID 发的 | LSP 头 | `0000.0000.0002` |
| 是不是重分发进来的 | TLV 135 的 **X 位** | `Ext. Cost : 0`（直连是 `NULL`） |
| 外部 cost | Ext.Cost | `0` |
| 管理 tag | TLV 135 sub-TLV | `Admin Tag : -`，空 |
| 到注入点的内部距离 | Int.Cost | `20` |

**X 位只表达"来自 IS-IS 外部"，不表达"来自哪个协议"。** `import-route ospf/static/direct` 进来后 X 位都是 1。

OSPF Type-5 同理：只有 Adv Router、Metric、E1/E2、Tag、FA，**没有源协议字段**。Tag 是唯一能人工塞来源信息的槽位，且是纯约定。

## 有内建防环的机制都不适用

| 机制 | 手段 | 适用 OSPF↔IS-IS |
|---|---|---|
| BGP | AS_PATH | ❌ |
| OSPF L1/L2 | Down bit | ❌ 只防 L1→L2→back |
| IS-IS L1/L2 | Up/Down bit | ❌ 只防域内泄漏 |
| MPLS VPN | RD/RT | ❌ |

**Tag 的作用：人工把缺失的"来源协议"字段补回去。**

# 五、RIB 订阅机制

## `import-route` 是长期挂载的订阅，不是一次性命令

```
RIB 每次变更
   → 主动向订阅者推送 delta（增量）
        → 每条通知自带 Proto + Process ID
             → 协议用 import-route 做谓词过滤
                  → 命中的写进重分发表
```

敲下命令时做三件事：注册过滤器 → 全表扫一次（配置事件）→ 长期监听。

## 两种"不关心"，别混

| 层 | 过滤粒度 | 事件是否送达协议 |
|---|---|---|
| **订阅**（RIB 侧） | 协议 + 进程 | 不匹配的**根本不推送** |
| **求值**（协议侧） | D 位、route-policy、filter-policy | 已送达，协议自己丢弃 |

**订阅的粒度是协议，不是前缀。** 无法"只订阅某个前缀"，只能靠 route-policy 在求值阶段层层筛选——而筛选永远发生在事件到达之后。

两个推论：
- 改 route-policy 不必重敲 `import-route`（事件一直在收，只是本地丢了）
- 将来才出现的前缀也能自动捕获（订阅里没有前缀名，只有协议名）

## 三种事件

| 事件 | 触发 | 动作 |
|---|---|---|
| **Add** | 新路由算出 / Inactive→Active | 命中则加入 |
| **Delete** | 路由彻底移除 | 从发布集移除 |
| **Modify** | 下一跳、cost、**preference、D 位**变了 | 重跑谓词，按新属性决定去留 |

**本实验走的是 Modify**：

```
变更前：5.5.5.5 O_ASE  Pref 150  Flags D   ← 命中
变更后：5.5.5.5 O_ASE  Pref 150  Flags –   ← D 位清除，不命中
```

**条目从未离开 RIB，变的是裁决状态位。** 如果只在 Add/Delete 时通知，系统会卡死在"路由还在但已失效却仍继续通告"。

## RIB 不做表对比

RIB 不保存快照、不做全表 diff，只推**逐条事件**。协议端也不比对旧表，只问一句：**这个前缀在我当前发布集里吗？**

| 事件 | 判断 | 结果 |
|---|---|---|
| Delete 一条从未命中的路由 | 不在发布集 | 零动作，不重建 |
| Delete 一条已在发布集的 | 在发布集 | 移除 → 重建 |
| Modify 一条从未命中、新属性也不命中 | 不在，且不命中 | 零动作 |
| Modify 一条从未命中、新属性命中 | 不在，但命中 | **加入** → 重建 |
| Modify 一条已在发布集、新属性不命中 | 在，但不命中 | 移除 → 重建 |

**"少了一条与谓词无关的路由" = 第一条，零动作**：不重建、不涨序列号、不跑 SPF、邻居无感知。

三条理由：性能（O(变化量) vs O(表大小)）、语义（LSP 只承载"我要发什么"）、收敛（无关变化触发重建会放大成全网 SPF 抖动）。

### 唯一例外：级联

```
R2 上 10.0.15.0/24 断
   ↓（RIB 重算）
R2 的 OSPF 路由 5.5.5.5 下一跳不可达 → 也消失
   ↓（这一条才是"与谓词有关"的 Delete）
5.5.5.5 从发布集移除 → LSP 重建
```

**触发重建的是第二条事件，不是第一条。** 不是 RIB 帮你推断关联，而是路由重算本身产生了新的相关 delta。

## 为什么不能等 900 秒刷新

会形成最长 15 分钟的错误通告窗口：持续通告一条自己不走的路 → 次优或环路，双向场景下震荡放大。

**订阅保证快（毫秒级），节流保证不失控（50ms），两个设计是配套的。**

## 哪些命令订阅 RIB

| 命令 | 视图 | 订阅什么 |
|---|---|---|
| `import-route <proto> [pid]` | ospf/isis/rip/bgp | 该协议 **Active** 路由 |
| `default-route-advertise` | ospf | `0.0.0.0/0` 是否存在 |
| `default-route originate` | isis/rip | 同上 |
| `network <prefix> [mask]` | bgp | RIB 中精确匹配且 Active |
| `aggregate` | bgp | 明细路由是否存在 |
| `filter-policy export` | ospf/isis/rip | 重分发集合（二级过滤） |
| 下一跳递归 | bgp | 下一跳可达性 |
| `ip route-static ... track/bfd` | 系统 | 递归下一跳解析 |

看着像但不是：

| 命令 | 为什么不是 |
|---|---|
| `display ip routing-table` | 一次性快照 |
| PBR | 每报文查一次，路由变了不知道 |
| `traffic-filter` / ACL | 作用在转发面 |
| `ospf enable` / `isis enable` | 方向相反，推给 RIB |
| `route-policy` / `acl` / `ip-prefix` | 不订阅，但**被订阅者引用**；改了引用者会重算 |

**订阅方向是从 RIB 向外的**：RIB 不记谁订阅了，只在自己条目变化时推 delta。所以一个很小的 pref 变化会让所有引用该前缀的订阅者同时重算——**这就是改 preference 危险的原因**。

# 六、IS-IS LSP 与 OSPF LSA 的关键差异

## 发布单位

| | OSPF | IS-IS |
|---|---|---|
| 单前缀粒度删除 | ✅ **可以**，flush（Age=3600） | ❌ 不行 |
| 整包删除 | LSA flush | Purge LSP（删整条） |
| 删一条前缀 | 一条 LSA | 必须整 LSP 重生，**seq +1** |
| 撤销时 seq | **不涨** | +1 |

IS-IS 把**一个节点的所有路由打包成一条 LSP**：

```
LSP (System ID 0000.0000.0003, seq 0x0000000A)
 ├── TLV 22   邻接关系
 ├── TLV 135  扩展 IP 可达性
 │     ├── 10.0.34.0/24
 │     ├── 10.0.13.0/24
 │     ├── 1.1.1.1/32
 │     ├── 10.0.15.0/24
 │     └── 5.5.5.5/32      ← 只是其中一个条目
 └── TLV 132  接口地址
```

"撤回 5.5.5.5" = 重分发表重算 → **整条 LSP 重生** → 对端整条替换 → SPF 发现少了这一项。**没有"删除单个前缀"的报文。**

## LSP 里少一条前缀，三种可能只有一种符合

| 机制 | 粒度 | 序列号 | 本实验 |
|---|---|---|---|
| **内容变更重生** | 单前缀 | **+1** | ✅ |
| **Purge** | **整条 LSP** | 不 +1 | ❌ |
| **老化/刷新失败** | **整条 LSP** | 不 +1 | ❌ |

**决定性反证**：R3 重分发表里其他三条都在。若是老化或清除，四条会同时消失并触发邻居 down + SPF 重建。

## 定时器尺度（差两个数量级）

| 定时器 | 默认 | 作用 |
|---|---|---|
| LSP Refresh | **900 s** | 重新泛洪，**序列号不变**，只重置寿命 |
| LSP Max Age | **1200 s** | 寿命归零 → 对端视为失效 |
| Zero Age Lifetime | 600 s | 归零后保留多久才删除 |
| **LSP-Throttle** | **50 ms** | 两次重生之间的最小间隔 |

**反直觉点：周期刷新不涨序列号。** 所以 `0x80000006` 只能是"内容变了 6 次"，不可能是"刷了 6 次"。

从引入到锁死只用了**几秒**，900s/1200s 的定时器来不及动。

## LSP-Throttle 是什么

> 同一条 LSP 两次生成之间的最小间隔，默认 50ms。间隔内的多次变更攒着，到点**合并**成一次生成。是合并，不是丢弃。

```
display isis brief
  Timers: Csnp: L1 10  L2 10 , Retransmit: L12 5 , Hello: L1 10 L2 10 ,
  Hello Multiplier: L1 3  L2 3 , LSP-Throttle Timer: L12 50
```

| 字段 | 含义 |
|---|---|
| `Csnp 10` | DIS 每 10 秒发 CSNP 同步数据库 |
| `Retransmit 5` | 点对点未确认 5 秒重传 |
| `Hello 10 × 3` | 邻居 Hold = 30 秒 |
| `LSP-Throttle 50` | LSP 重生最小间隔 |

**它决定了那场毫秒级赛跑的时间分辨率。**

## TLV 135 编码

```
TLV 135 (5.5.5.5/32)
 ├─ metric   = 外部 cost（本实验 0，因为没给 cost）
 ├─ X 位     = 1   ← "来自 IS-IS 外部重分发"
 ├─ R 位     = 是否重分发到其他 level
 ├─ 前缀长度 32 + 5.5.5.5
 └─ sub-TLV: 32-bit tag（本实验空）
```

**ExtCost 默认 0 是环能轻易锁死的重要原因**：外部代价 0 意味着不比任何直连更贵。规范做法 `import-route ospf 1 cost 20`。

## 对端选路顺序

```
第一比 Level     同前缀 L1 和 L2 都有 → 默认 L1 优先
第二比 metric    IntCost（到通告者的 SPF 距离）+ ExtCost
第三比 相等则 ECMP（最多 8 条）
```

**全程没有"哪个协议"参与**，所有候选都是 IS-IS 自己的 LSP。

```
[R3] display isis route 5.5.5.5 verbose
  Int.Cost 20   Ext.Cost 0   Src Count 1
  NextHop 10.0.34.4   Flags : A/-/-/-
```

## Flags 速查

| 位 | 含义 |
|---|---|
| **D** | Direct，SPF 树叶子 |
| **A** | Added to URT，已装进路由表 |
| **L** | **Advertised in LSPs，本机 LSP 里有这条** |
| **S** | IGP Shortcut 参与 |
| **U** | Up/Down bit 置位（L2 泄漏到 L1） |

**`L` 位是双稳态的物理证据：**

```
[R3] 5.5.5.5       Flags: A/-/-/-    学了但我不发 → 不是 IS-IS 注入源
[R2] 10.0.34.0/24  Flags: D/-/L/-    直连，既入 RIB 又广告
```

# 七、双稳态锁的形成

## 角色分工

```
[R2] display isis route   Level-2 Redistribute Table
  O  5.5.5.5/32     0  0    ← 有：R2 负责 OSPF→IS-IS

[R3] display isis route   Level-2 Redistribute Table
  （没有 5.5.5.5）           ← R3 不往 IS-IS 注入它
```

```
[R2] display ip routing-table 5.5.5.5 verbose
  O_ASE    150  Active     ← OSPF 版本生效

[R3] display ip routing-table 5.5.5.5 verbose
  ISIS-L2   15  Active     ← IS-IS 版本生效
  O_ASE    150  Inactive   ← OSPF 版本被压掉
```

| 设备 | RIB 生效版本 | `import-route ospf` | `import-route isis` |
|---|---|---|---|
| R2 | O_ASE Active | ✅ 有东西可注入 | ❌ 无 IS-IS 路由 |
| R3 | ISIS-L2 Active | ❌ 无活跃 OSPF 路由 | ✅ 有东西可注入 |

## 两个关键机制

**① 自己注入的路由不回流自己的 RIB（水平分割）**

```
[R2] Redistribute Table → 有 O 5.5.5.5/32
[R2] Forwarding Table   → 没有 5.5.5.5
```

R2 把 5.5.5.5 放进自己发出的 LSP，但不把自产 IS-IS 前缀装回自己 RIB。所以 R2 的 OSPF 副本永远 Active。

**② preference 压制（15 < 150）**

**① + ② = 不对称锁定**：先注入的一方不会因自己的注入失去触发源，后到的一方被永久压制。

## 双稳态

| | R2 | R3 |
|---|---|---|
| 稳定态 A（本实验） | OSPF→IS-IS | IS-IS→OSPF |
| 稳定态 B（镜像） | IS-IS→OSPF | OSPF→IS-IS |

两个都合法、都不成环。落哪一侧由**毫秒级时序**决定，之后靠周期刷新永久固化。

**中间态（两台都双向）逻辑上自相矛盾**：两台都注入 IS-IS → 两台都收到对方副本 → 两台 OSPF 副本同时消失 → 两台都撤回，谁也维持不住。

## 逐前缀独立锁定（本实验最有力的证据）

```
[R2] Redistribute Table → 有 5.5.5.5，没有 1.1.1.1
[R3] Redistribute Table → 有 1.1.1.1，没有 5.5.5.5
```

完全镜像：

```
5.5.5.5:  R5 ─OSPF→ R2 ══IS-IS══→ R3 ─OSPF→ R1
1.1.1.1:  R1 ─OSPF→ R3 ══IS-IS══→ R2 ─OSPF→ R1
```

**同一对 ASBR 可以在这个前缀当注入方、在那个前缀当回灌方。** 因为 preference 比较是逐前缀做的。

# 八、重分发反馈环

## 时间线

| 时刻 | R2 | R3 |
|---|---|---|
| T0 | 5.5.5.5 = O_ASE **Active** | 同 |
| T1 | 注入 IS-IS，ExtCost 0 | 同 |
| T2 | 收到对方 LSP → IS-IS 副本压过 OSPF → **Inactive** | 同 |
| T3 | 抓不到 → 重建 LSP，丢掉 5.5.5.5 | 同 |
| T4 | 收到对方撤回 → IS-IS 副本消失 → OSPF 回 **Active** | 同 |
| T5 | **重新注入** | 同 |
| → T2 | 循环 | 循环 |

**T3 两台同时撤回，T4 两台同时恢复，环自我维持。**

"一台快一点"只在**环的出口**成立：某轮 A 的新 LSP 到达 B 早于 B 执行注入，B 被压住不再注入，A 收不到 B 的 LSP 就一直注入。**决定的是最后那一轮。**

## 序列号解读（重要修正）

```
R5 直连：  seq# 0x80000001
R3 回灌：  seq# 0x80000006
```

Type-5 初始 `0x80000001`，每**重新产生**一次 +1，到 `0x7FFFFFFF` 回绕。

- 只能证明**被重新产生过 5 次**
- **不等于撤销过 5 次**——撤销用同序列号 + Age=3600，**不 +1**
- +1 的时机：路由重新出现，或内容变了（metric、FA、tag）

所以也可能是手敲配置时 RIB 反复变化留下的（R3 重分发表里 10.0.12.0、1.1.1.1 进进出出）。

## 为什么看不到抖动

环的周期是**几十到几百毫秒**，`display` 需要几秒。看到时早已锁定。

```

# seq 不动 → 已锁死；每 1~2 秒 +1 → 还在振荡带
```

# 九、OSPF 侧的订阅同样在跑

`ospf 1` 下 `import-route isis 1` 挂的谓词：`Proto == IS-IS && D位 == 1`

**证据：**

```
[R1] display ospf routing   Routing for ASEs
  10.0.24.0/24   1  Type2  AdvRouter 2.2.2.2    ← IS-IS 域内链路
  10.0.24.0/24   1  Type2  AdvRouter 3.3.3.3
  10.0.34.0/24   1  Type2  AdvRouter 2.2.2.2
  10.0.34.0/24   1  Type2  AdvRouter 3.3.3.3
  1.1.1.1/32     1  Type2  AdvRouter 2.2.2.2    ← 反向锁定
  5.5.5.5/32     1  Type2  AdvRouter 3.3.3.3    ← 回灌
```

`10.0.24.0`、`10.0.34.0` 是 IS-IS 域内链路，OSPF 里本不存在，能变成 ASE 的唯一路径就是这个订阅被执行了。

## OSPF 侧订阅后的动作

```
① 对变更项重跑谓词
      ↓ 命中
② 写进重分发表
      ↓
③ 生成 Type-5 ASE：AdvRouter = 自己，metric 1，E2，Tag 1
      ↓
④ 泛洪给区域内邻居
      ↓
⑤ 对端装 LSDB → SPF → RIB → 转发
```

没命中反向执行：从分发表移除 → 发同 seq、Age=3600 的 flush LSA（**不涨 seq**）→ 对端删除。

## 双向订阅 = 环的结构定义

```
        ┌──────── OSPF 进程 ────────┐
        │ import-route isis 1        │
        └──────────▲─────────────────┘
                   │ RIB 推 delta
              ┌────┴─────┐
              │   RIB    │  preference 裁决
              └────▲─────┘
                   │ RIB 推 delta
        ┌──────────▼─────────────────┐
        │ IS-IS 进程                  │
        │ import-route ospf 1         │
        └────────────────────────────┘
```

**两个谓词挂在同一张 RIB 上，一个的输出（ASE）改变另一个的输入（IS-IS 路由），反之亦然。** 这不是某台配错，而是拓扑形态自带正反馈。

# 十、解决思路

## ① Tag 互斥（标准做法）

```
isis 1
 import-route ospf 1 tag 200
ospf 1
 import-route isis 1 tag 300 route-policy NO_BACK

route-policy NO_BACK deny node 10
 if-match tag 200
route-policy NO_BACK permit node 20
```

## ② 单点注入

只在一台 ASBR 做双向，另一台单向或不做。

## ③ `filter-policy import` 强制翻转角色

```
isis 1
 filter-policy 2000 import
acl 2000
 rule deny source 5.5.5.5 0
 rule permit
```

```
R3 的 IS-IS 路由表过滤掉 5.5.5.5
   → ISIS-L2 条目消失 → OSPF 版本重获 D 位
      → RIB 推 Modify → 谓词命中
         → 5.5.5.5 重新进入重分发表 → LSP 重生 → 角色换边
```

**只改一处 filter-policy，`import-route ospf 1` 一个字没动**——订阅机制的直接体现。

## ④ 改 preference（不推荐）

把 IS-IS 调到 200。会让全网 IS-IS 域内路由被 OSPF 压制，且触发大量订阅者同时重算。

## ⑤ 给引入加 cost（本实验遗漏）

```
isis 1
 import-route ospf 1 cost 20
```

ExtCost 0 意味着不比任何直连更贵，是环轻易锁死的重要原因。

# 十二、一句话总收束

```
RIB 是裁判 → preference 是规则 → D 位是裁决结果
   → 订阅是通知机制 → 谓词是过滤器 → LSP/LSA 是快照
```

**5.5.5.5 从 LSP 里消失，不是老化、不是超时，而是裁判改了判，订阅者跟着更新了快照。**

**谓词是合取过滤，发布集是过滤结果，LSP 是发布集的快照。RIB 一变就重跑过滤，结果与上一版不同才重新打包——打包单位是整条 LSP，所以"删一条"在线上表现为"整包换一版"。**

**双稳态能停下来，靠的就是这道闸门：只有一边能通过 RIB 的 D 位检查。**
